## Bugs encontrados (código)

### 🟡 1. Doble `<JarvisCore>` con el mismo `layoutId` (posible parpadeo del orbe)
`jarvis-core.tsx` lleva `layoutId="jarvis-core"` (lo usa Motion para el "vuelo" del orbe en la
bienvenida) y su propio comentario advierte: *"Nunca debe haber dos `<JarvisCore>` montados a la
vez"*. Pero al **abrir el panel** quedan **dos** montados: el del header (`jarvis-header-orb`) y el
del header del panel (`jarvis-panel.tsx`). Motion puede confundir el layout → parpadeo / salto del
orbe.
- **Fix sugerido:** el orbe del panel debe ser un orbe **plano sin `layoutId`** (un `JarvisCore`
  variante "static", o un div con el mismo gradiente). No reutilizar el que tiene `layoutId`.

### 🟡 2. Temperatura 0 es imposible de guardar
En `ai-config-form.tsx`: `temperature: Number.parseFloat(temperature) || 0.7`. Como `0` es
*falsy*, poner temperatura **0** la convierte en **0.7**.
- **Fix:** usar `Number.isFinite(n) ? n : 0.7` en vez de `|| 0.7`.

### 🟡 3. Se puede "Activar" el asistente sin cargar la API key
En el admin se puede tildar **"Asistente activado"** y Guardar sin key. El chat luego falla con
"sin_config". No rompe (degrada con mensaje claro), pero es confuso.
- **Fix:** no permitir `enabled` sin `hasKey` (o advertir al guardar).

### 🟢 4. Markdown liviano no soporta links
El render propio (`MarkdownLite`) hace bold/italic/code/listas/headings, pero `[texto](url)` se
muestra **literal**. Las citas del RAG (`[METODO_TBM_CANONICO.md]`) se ven bien (es el efecto
buscado), así que es menor; si el modelo devuelve links reales, quedan sin formatear.

### 🟢 5. Re-ingesta deja chunks huérfanos
`scripts/ingest-knowledge.mjs` borra/reinserta **por `source`**. Si se **quita** un doc de la
lista `DOCS`, sus chunks viejos quedan en `knowledge_chunks`. Limpieza manual o un flag `--prune`.

### 🟢 6. Umbral de similitud (0.3) algo laxo
`jarvis-retrieval.ts` filtra `similarity > 0.3`. Con gte-small los chunks relevantes dieron 0.85+,
así que 0.3 puede colar fragmentos poco relevantes (ruido en el contexto). Tunear si se nota.

### 🟢 7. El panel no atrapa el foco (a11y)
El slide-over es `role="dialog"` y cierra con Esc, pero el **Tab puede escaparse** al contenido de
atrás (sin focus-trap). Menor.

### 🟢 8. `embed` Edge Function — `verify_jwt` deja entrar a cualquier autenticado
La función exige un JWT válido del proyecto, pero eso incluye el **anon key**: un tercero con la
anon key podría llamarla y consumir compute de embeddings. Riesgo bajo (solo devuelve vectores de
texto que le pasen), pero idealmente restringir a service-role (chequear el claim `role`).

## A verificar en producción (no comprobado desde acá)

### 🔴/🟡 9. ¿La WEB (Vercel) tiene `SUPABASE_SERVICE_ROLE_KEY`?
El chat **entero** depende de `createAdminClient` (service-role) para leer `ai_config` + la key.
Sin esa env var en el proyecto Vercel `tbm-app`, el chat responde **"sin_config"**. *Probablemente
ya está* (la usa el cron `/api/cron/daily`), pero **confirmar**.

### 🟡 10. ¿El RAG funciona en prod? (depende del formato de la key)
La recuperación llama a la Edge Function `embed` con `Authorization: Bearer <service_role>`, que
debe pasar el `verify_jwt` del gateway. Si la `SUPABASE_SERVICE_ROLE_KEY` del web fuese del
**formato nuevo** (`sb_secret_…`, no un JWT), el `embed` daría 401 → el RAG **degrada en silencio**
(el chat sigue, pero **sin citar el material**). En el proyecto la key local es JWT válido (la
ingesta funcionó), así que probablemente OK — confirmar en prod.

## Checklist de prueba manual (para Sebas, en prod)

1. **Chat base:** admin → Asistente IA con key + **activado** → en la web, abrir el orbe y
   preguntar algo → debe responder. *(si "no disponible" → falta env/activar)*
2. **RAG:** preguntar algo del método ("¿qué es LOST?", "¿temor del perfil C?") → la respuesta debe
   reflejar el material canónico. Si **nunca** se nota el material → revisar punto 10.
3. **Markdown:** pedir "dame una lista de 3 pasos" → ver viñetas/negritas formateadas.
4. **Streaming:** ver el cursor parpadeando mientras escribe; probar **Parar** a mitad.
5. **Acciones UX:** copiar respuesta, **Nueva conversación** (＋), textarea que crece, Esc cierra.
6. **Mobile:** abrir en teléfono → panel a ancho completo, usable.
